# Actionable editorial queue (PR-29, issue #194)

The existing report now retains stable collection/record IDs, owner or explicit unassigned status, primary source links and a source-file link at the exact checkout commit. Line numbers are derived from that linked commit, so uncommitted edits cannot produce a misleading GitHub line. The Markdown queue states why each item needs attention and is uploaded alongside JSON by the existing operations job; the CI step summary already consumes this report.

Optional `--source-drift <bounded-report.json>` attaches changed/blocked/unverified canonical-source context from PR-27's typed report, explicitly labeled fetch/diff is not review. It never changes review dates or source prose. The queue remains independently usable when no drift report is supplied.

An explicit `--issue-draft COLLECTION:ID` writes a local JSON draft containing a stable marker and prefilled issue URL. It never publishes an issue. Optional `--existing-issues <JSON>` detects an existing marker and suppresses the new-issue URL. This detects tasks containing the stable marker; older unmarked issues still require an editor's search. Existing issue evidence must be a bounded body/url array (for example an explicit read-only `gh issue list --state all --limit1000 --json body,url` export). The draft requests an evidence-backed review decision, affected paths/checks and preservation of unrelated dates.

Example: `npm run report:content-reviews -- --allow-overdue --artifact .artifacts/content-reviews/local.json --issue-draft SECURITY_INCIDENT_RECORDS:memoless-spam-2026-08`. Add `--source-drift` and `--existing-issues` only with the relevant supplied reports. Evidence-only mode remains explicit and cannot approve a release. Owner assignment is metadata/exception ownership, not a newly assigned reviewer.
