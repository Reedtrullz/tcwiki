# PR-23 printable curated articles and portable citations

Deep-dive articles now offer browser print, text/Markdown citation copy and a citation-only text download. Each citation uses the canonical article/current section URL, actual wiki review/due dates, confidence, evidence boundary, all source URLs, retrieval dates and source notes. Clipboard failure exposes selectable text; no article text or live dashboard sample is redistributed or silently cached. Full article exports remain conditional on the owner licensing choice in #160.

Print CSS produces a light readable article, one expanded source list, canonical URL and actual review metadata, and hides global navigation and citation controls. Native beforeprint/afterprint opens article details and restores their prior screen state. Tables wrap to the page width and rows avoid page breaks; code can wrap. The initial A4 proof revealed excessive nested source cards, so the final print uses one metadata source list rather than duplicating that screen layout.

Validation: red missing-helper tests then two passing citation units; full658units/57files, types/lint/content, both runtime builds and Next standalone smoke passed. Eleven article/source-posture/citation browser checks passed per runtime before the final download/print refinements. Final four citation/download/fallback/print-state checks passed on desktop+mobile per runtime. A local Chromium A4 PDF proof was generated and first-page source metadata plus the page-three four-column claim table were visually inspected. This checks browser rendering, not a physical printer or spoken PDF accessibility. The first build failed because the test used an unsupported null argument to toHaveAttribute; it was corrected to an absence assertion and final builds pass. The attempted bundled Python fitz proof renderer was unavailable; bundled pdfinfo/pdftoppm rendered the proof successfully without installing dependencies.

The change adds no PDF service, accounts or remote recording. Original registry review dates and historical boundaries are retained. No main merge or deployment.
