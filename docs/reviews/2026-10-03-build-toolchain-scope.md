# Cloudflare build tooling dependency scope

PR230 CI37085135892 failed `audit:prod` on newly indexed [GHSA-vfj7-8cjw-p6xm](https://github.com/advisories/GHSA-vfj7-8cjw-p6xm). The advisory lists braces through3.0.3 with no patched release as of2026-10-03. The npm chain is vinext -> vite-plugin-commonjs -> vite-plugin-dynamic-import -> fast-glob -> micromatch -> braces; npm's proposed downgrade to vinext0.0.15 is not compatible with this project.

Consumer review found vinext and @vinext/cloudflare used by Vite/Cloudflare build and deployment tooling. Neither is imported by wiki application routes or the Worker entrypoint. The Next Docker runner copies the standalone traced output; the actual standalone node_modules has neither vinext nor braces. Cloudflare runs the built Worker modules, and the checked server external manifest/module imports do not require braces or the commonjs build plugin. Move these two tools to devDependencies, retaining their exact locked versions/integrities. Build/CI still installs them; deployment ships the same bundle.

Production dependency audit returns zero after a clean install, and the production dependency tree excludes vinext, its Cloudflare CLI and braces. This is correct dependency classification, not a patch for the vulnerable build tools: full development audit still reports their exposure. Builds only process repository-controlled patterns, and no new untrusted-pattern input is introduced. Both target builds/standalone smoke and their existing browser gates must pass before accepting the candidate; source/artifact proof remains separate from production rollout.
