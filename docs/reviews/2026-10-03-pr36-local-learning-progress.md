# PR-36: opt-in reading progress without an account

Deep-dive readers can choose a registry-defined path in the URL, then explicitly enable browser-local read marks and a bookmark. The bookmark snapshots the actual article review date; a newer authored review is disclosed without asserting understanding or competence. Unrelated query parameters and fragments remain intact. Nothing is written before opt-in; disable/reset deletes the local key. Import is an explicit replacement action and export downloads ordinary JSON. These controls are hidden in article printing.

The version1 schema accepts at most64KiB/100records with exact keys, stable IDs, real date formats and locally derived path URLs. Removed paths/articles are ignored with a recovery link; unsupported, malformed, oversized and duplicate data cannot overwrite existing progress. Storage read/write/reset failures leave article navigation usable. The client receives a small server-created path catalog rather than importing all curated data into its bundle. No accounts, wallet identity, analytics, notifications, service worker or article cache were added.

Validation: six meaningful focused unit cases plus all707units/66files, types, scoped lint and content checks passed. The worker’s preliminary checks preceded a catalog API refactor; parent review corrected two missing catalog arguments before the current passing checks. Both final builds and standalone smoke passed. Each actual built Next and WikiDO runtime passed14desktop/mobile reader, article-shell, heading-anchor and rendered-link checks. The reading journey covers opt-in, exact review-date/read snapshots, reload/resume, downloaded JSON, delete/import, unavailable storage, obsolete ID recovery, incompatible-import retention,320pxcontainment and automated WCAG rules. Initial test storage clearing was corrected to run once, so reload actually tests retention. Reading history was not transmitted to a service.

The authored review date is a bookmark comparison signal, not a full-text revision or supersession detector. Expansion to richer change tracking requires maintained revision evidence. Base PR265. No main merge or deployment. Commits are unsigned because the interactive signer is unavailable.
