# Requested pinning and response-height evidence

Workplan PR44. A height in a source URL proves a requested pin. `SourceMeta.heightPinning` now records requestedHeight, optional observedHeight and verified/unverified separately. Only an equal safe integer in THORNode's `grpc-metadata-x-cosmos-block-height` response header produces verified. Absent/unexposed headers remain unverified; malformed/mismatched headers reject that provider through existing fallback. Exact source URLs retain the requested pin, and the strict readiness validator rejects manufactured equality or a different URL height. Matching headers are provider metadata evidence, not cryptographic state proofs.

Fee/POL sourceFreshness includes the combined required/requested-source result. A combined result is verified only when every listed requested read echoes that height; unrelated provider snapshots are never mixed. The existing snapshotPinned boolean is a compatibility flag for request construction, explicitly documented as such. UI labels now distinguish response verification from a requested height. Network lastblock reconciliation retains its separate body-height validation. The independent chain script uses the same small header parser and records per-provider evidence, with its own lag/freshness policy unchanged.

Capability evidence: the [THORNode SDK-v50 migration changelog](https://gitlab.com/thorchain/thornode/-/merge_requests/3756/commits) documents height query injection and the REST response header.
