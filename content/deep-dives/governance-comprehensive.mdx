This section breaks down every ADR by *how* it passed (or didn't) — which ones were genuine nail-biters, which ones sailed through, and which ones only passed because a Motion to Bypass avoided a formal vote.

### Clear Winners (>70% support, little controversy)

- **ADR-011 Lending — 73.3% (63/86, 1 dissent).** "The biggest, and most difficult feature since MCCN." Even with 86 active validators, only one node voted against. Lending took nearly a year from inception to launch, and node operators were urged to vote explicitly because the community "will interpret a lack of vote as being apathetic."
- **ADR-016 Affiliate Fee — 72% (72/100).** The cleanest large-validator-set win in the archive. Reached supermajority within days, finished with 28 explicit dissents (all zeros, no commentary relays).
- **ADR-008 DOFM — 68.2% (58/85) — close-but-comfortable.** Passed the supermajority threshold on the last day of the 10-day window. The community had to publicly campaign for the last two votes ("We need two more votes from the nodes to pass adr 008. Any suggestions why they need so much time?") and ghostrider4486 was openly frustrated: "comon guys weak up and pass ADR 008!? devs please say something!"

### Close Calls (passed but barely, or required active campaigning)

- **ADR-029 Revenue Share (SwapKit) — 58.9% (56/95).** The closest of the recent ADRs. Started the voting period needing active campaigning, with several nodes openly on the fence. SamYap and others ran a multi-week push ("Reminder for the NO to vote ADR029 (thanks SamYap) .. if there are any concerns to don't vote or vote against, it would be great to know why"). The YES vote only crossed 50% in the last days of the voting window.
- **ADR-012 Scale Lending — ~52% in favor at one snapshot.** This was the closest lending-related vote. Several nodes **later removed their votes** (climber2391: "It seems some nodes removed their vote towards ADR012. Is that right? Only 66 votes now. It used to be more than 70"). Vote decay and fatigue were real issues. Passed only because the 60M RUNE burn was bundled with the CR-200% change.
- **ADR-031 Rujira Long-Term Alignment — Option 1 (JV) won, but voting fatigue noted.** The vote request explicitly asked nodes to consider the recent $10M Asgard vault exploit and to choose a path forward. Option 1 was the strong consensus choice (sonofodin and aaluxx both endorsed it), but multiple commenters noted "voter fatigue" with simultaneous open votes (ADR-029, ADR-031, ADR-030, TORANCHOR mimirs all open at once).

### Passed via Motion to Bypass (no formal vote — interpretive as "no one objected loudly enough")

These ADRs did not go through a `make mimir` vote. Instead, a contributor called a Motion to Bypass, which means the ADR takes effect after 7 days unless a node operator files an explicit `make relay` dissent. They are *de facto* unanimous but did not receive a positive vote of confidence.

- **ADR-014 Reduce Saver Yield Target** — pluto_x1: "Motion to Bypass succeeds. Devs will proceed to implement."
- **ADR-015 Refund Synth Positions After Ragnarok** — same, in the same hour.
- **ADR-022 Per Block Swap Scoring** — familiarcow: "Discussion on this ADR has been ongoing for ~1 month. Devs are in consensus. Will be calling a motion to bypass a vote."
- **ADR-025 Move Dev Fund Address** — _sonofodin: "I expect there to be no resistance here, imo." (prophetic — none came).

### Contested / Controversial (passed but with significant opposition)

- **ADR-018 Core Protocol Sustainability.** Procedurally a Motion to Bypass, but with **strong public opposition** from yeguls, proofofsteve, multipartite, and others. The core concerns: (1) conflict of interest — 9R-controlled nodes would be voting on 9R's own funding; (2) ADR framework is not a funding framework; (3) the proposal was too centralizing; (4) Monero-style Community Crowdfunding System was proposed as a counter. **The ADR was amended to add a 3-year sunset clause** before passing. This was a hard-won compromise, not a clean win.
- **ADR-017 Burn System Income Lever.** The *mechanism* passed, but the *rate* has been gridlocked ever since. Current vote (Aug 2026): 5% — 35/95 (36.8%); 2.5% — 4/95 (4.2%); 1% — 25/95 (26.3%); 0.01% — 1/95 (1.1%). No single value has a supermajority.
- **ADR-009 Reserve Income & Fee Overhaul.** Procedurally passed, but the **Reserve Income section was removed before passage** as "contentiously large (may be addressed in a separate ADR)." The remaining USD-fee code shipped but `EnableUSDFees` was never set, so the protocol still uses RUNE-denominated fees. This is a *de facto* partial implementation.

### Rejected / Withdrawn

- **ADR-001 THORChat — not passed.** Merged as a proposal in 2022 but never received node support. The chrisgrc ADR audit from 2024-08-06 still lists this as "the only one [not passed] that has been merged as an ADR doc."
- **ADR-007 Increase Fund Migration & Churn Interval — withdrawn.** _sonofodin argued the proposal "utilizes the churn and migration which have their own purposes to solve a problem that is unrelating" and that the same problem was better solved by a refund PR. pluto_x1 agreed: "ADR 007 withdrawn. Alternative 1 is being pursued instead."

### Pending / Stuck Votes (as of Aug 2026)

- **ADR-019 AutoBond.** Open since 2024. moonmonkey_666: "Same solution: ADR 019" has been the punchline in dozens of debates about passive RUNE holders and bond providers, but no formal vote has been called.
- **ADR-020 App Layer.** Active in discussion, no formal vote.
- **ADR-024 System Income to POL.** "Rat's nest of discussion" per runetard. The vote is structurally unclear: "ADR024 > 1 = Yes — but yes to what? There are 4 possibilities as to how a Yes vote can be implemented." The original champion (cow) stepped down; boonedub took over. The discussion has stalled.

### 2021 -- The Summer of Exploits

The most turbulent year in THORChain history. Three exploits in 18 days, plus a full network halt from a token parsing bug.

**Jun 7 -- Repeated ETH Daemon Failures.** Persistent slashing from stuck sync.

**Jun 20 -- 9 Nodes Out of Sync on BTC / Near-Halt.** "Failing to do so will result in loss of funds. If not actioned asap, the network may need to be halted."

**Jun 28 -- HACK #1: ETH Parsing Exploit (~$140K stolen, Critical).** First major exploit. Attacker used custom attack contract on ETH router. Bifrost did not distinguish router events from called transactions. Network halted within ~1 hour. Funds declared safe overall.

Treasury covered stolen amount. Three bugs: (1) smart contract, (2) slow response, (3) ETH chain should have been halted earlier.
